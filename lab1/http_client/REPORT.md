# Отчёт по второй версии

## Организация параллельного обхода

В `crawlWebsite()` один раз создаётся постоянная группа рабочих потоков. Потоки
не создаются заново для отдельных страниц или батчей. Они берут URL из общей
очереди `toVisit`, а сетевой запрос, разбор HTML, нормализацию ссылок и проверку
домена выполняют без удержания общего мьютекса.

Мьютекс состояния защищает только:

- очередь `toVisit`
- множество `visited`
- карту `siteMap`
- счётчик `pendingTasks`
- признаки остановки и исключение рабочего потока

`pendingTasks` равен числу URL в очереди плюс числу обрабатываемых URL. Когда
счётчик становится равным нулю, новых ссылок уже появиться не может и все
потоки завершаются.

## Исправления по замечаниям

### 1. Вывод вне мьютекса состояния

Сообщение `Обработано: ...` сначала формируется в локальном
`std::ostringstream`. Изменения `siteMap`, `visited`, очереди и
`pendingTasks` выполняются под общим мьютексом, после чего он освобождается.
После этого сообщение выводится в консоль.

Для консоли используется отдельный `consoleMutex`. Он не блокирует очередь
задач и не мешает другим потокам получать URL. Этот же мьютекс защищает
диагностику `std::cerr` внутри `extractLinks()`, поэтому сообщения разных
потоков не перемешиваются.

### 2. Разбор URL вне критической секции

`getDomain(startUrl)` вызывается до запуска рабочих потоков. Для найденной
ссылки `normalizeUrl()` и `getDomain(normalizedLink)` вызываются во время
локальной обработки страницы, до захвата мьютекса состояния. Под мьютексом
остаётся только добавление уже подготовленных URL в общие контейнеры.

### 3. DNS до запуска рабочих потоков

До создания пула главный поток один раз выполняет:

```cpp
const ParsedUrl startParsed = parseUrl(startUrl);
const std::string serverIp = resolveIpv4(startParsed.host);
```

Рабочие `HttpClient` получают готовую пару «имя хоста — IPv4-адрес». Поэтому
`getaddrinfo()` не вызывается из рабочих потоков и медленный DNS не занимает
сразу все элементы пула. Все URL обхода предварительно фильтруются по домену.

POSIX-функция `getaddrinfo()` остаётся синхронной, поэтому первоначальное
разрешение имени может задержать запуск программы, но не исчерпывает рабочие
потоки.

### 4. Повторное использование соединений

Раньше для каждой страницы создавался новый `HttpClient`, новый `SSL_CTX` и
новый сокет с заголовком `Connection: close`.

Теперь каждый рабочий поток создаёт один собственный `HttpClient` перед циклом
обработки страниц. Объекты разных потоков не разделяют сокет, `SSL` или
`SSL_CTX`, поэтому гонок между ними нет. Внутри одного потока:

- `SSL_CTX` создаётся один раз
- запрос отправляется с `Connection: keep-alive`
- соединение повторно используется для того же хоста, порта и протокола
- при смене адреса или ответе `Connection: close` соединение закрывается
- если сервер закрыл сохранённое соединение между запросами, безопасный GET
  один раз повторяется через новый сокет.

Для коррекного keep-alive программа определяет границу HTTP-ответа по
`Content-Length` или `Transfer-Encoding: chunked`. Ответы без этих заголовков
читаются до закрытия соединения и повторно такой сокет не используется.

### 5. Сетевые таймауты

Подключение выполняется неблокирующим `connect()` с ожиданием через `poll()`.
Его таймаут равен 5 секундам

После подключения для сокета задаются:

```cpp
SO_RCVTIMEO = 10 секунд;
SO_SNDTIMEO = 10 секунд;
```

Таймауты действуют для HTTP и для OpenSSL, работающего поверх того же сокета.
Зависший сервер больше не удерживает рабочий поток бесконечно. Ошибка одной
страницы сохраняется в карте, после чего остальные задачи продолжают
обрабатываться.

### 6. Инициализация libxml2

Перед запуском потоков вызывается `xmlInitParser()`. Поэтому глобальное
состояние libxml2 инициализировано до одновременных вызовов `htmlReadDoc()`,
`xmlXPathEvalExpression()` и `xmlBuildURI()`.

Каждый поток создаёт собственные документы и XPath-контексты. Эти объекты между
потоками не разделяются.

### 7. Уведомление условной переменной

Очередь, `pendingTasks` и флаг `stopped` по-прежнему изменяются только под тем
же мьютексом, с которым проверяется предикат `condition.wait()`:

```cpp
condition.wait(lock, [&]() {
    return stopped || !toVisit.empty() || pendingTasks == 0;
});
```

После изменения состояния мьютекс освобождается и вызывается
`condition.notify_all()`. Потерянного пробуждения нет: проверка предиката и
переход `wait()` в ожидание атомарно согласованы одним мьютексом. При этом
разбуженные потоки могут сразу захватить мьютекс, а не просыпаться и ждать его
освобождения.

### 8. Исключения

Тело рабочего потока обёрнуто в `try/catch`. Неожиданное исключение сохраняется
в `std::exception_ptr`, устанавливается `stopped`, ожидающие потоки
пробуждаются. После `join()` исключение повторно выбрасывается в главном
потоке. Ошибка загрузки отдельного URL не останавливает весь обход.

## Сборка

Зависимости Ubuntu:

```bash
sudo apt update
sudo apt install build-essential cmake libssl-dev libxml2-dev
```

Сборка и запуск:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
./build/http_client https://example.com 10 4
```

В архиве также находится собранный Linux x86-64 файл:

```bash
./bin/http_client https://example.com 10 4
```
