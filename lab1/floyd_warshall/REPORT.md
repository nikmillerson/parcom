# Отчет для второй версии
## Назначение программы

## Распределение работы

Количество потоков определяется через `std::thread::hardware_concurrency()` и
ограничивается количеством вершин. Для пустого графа выполняется ранний
возврат, поэтому барьер с нулевым числом участников не создаётся.

Каждый поток получает непрерывный блок строк:

```cpp
int begin = n * threadId / numThreads;
int end = n * (threadId + 1) / numThreads;
```

Такая формула покрывает все строки без пересечений. Если `n` не кратно числу
потоков, размеры блоков отличаются не более чем на одну строку. Непрерывные
блоки также уменьшают количество границ между областями памяти, с которыми
работают разные потоки.

## Снимки опорной строки и столбца

Во время итерации `k` алгоритму нужны значения:

```text
dist[i][k]
dist[k][j]
next[i][k]
```

Чтение этих элементов прямо из изменяемых матриц могло бы привести к гонке.
Поэтому перед обновлением создаются три снимка:

```cpp
columnK[i] = dist[i][k];
rowK[j] = dist[k][j];
nextToK[i] = next[i][k];
```

Каждый рабочий поток
заполняет элементы `rowK`, `columnK` и `nextToK` из своего непрерывного блока.
Записи разных потоков не пересекаются, поэтому подготовка выполняется
параллельно и не создаёт дополнительной работы для потока 0.

Массивы выделяются один раз до запуска потоков и повторно используются на всех
итерациях.

## Использование барьера

В барьере участвуют только рабочие потоки:

```cpp
std::barrier syncPoint(numThreads);
```

На каждой итерации `k` барьер используется два раза:

1. После параллельного заполнения снимков. Ни один поток не начнёт изменять
   матрицы, пока остальные не закончат чтение опорной строки и столбца.
2. После обновления блоков строк. Ни один поток не начнёт подготавливать снимки
   для следующего `k`, пока остальные не закончат текущую итерацию.

Барьер также обеспечивает видимость записанных значений другим потокам после
завершения фазы.

## Отсутствие гонок данных

- `rowK`, `columnK` и `nextToK` заполняются непересекающимися блоками, а после
  первого барьера используются только для чтения;
- `dist[i][j]` и `next[i][j]` изменяет только поток, которому принадлежит строка
  `i`;
- второй барьер отделяет записи текущей итерации от чтений следующей;
- `exceptions[threadId]` записывается только соответствующим потоком и читается
  основным потоком после `join()`.

Таким образом, вычисление соответствует формуле:

```text
dist_new[i][j] = min(dist_old[i][j],
                     dist_old[i][k] + dist_old[k][j])
```

## Обработка исключений

Подготовка снимков и обновление строк выполняются внутри `try/catch`. Если в
рабочем потоке возникает исключение, оно сохраняется в
`exceptions[threadId]`, а атомарный флаг `failed` становится равным `true`.

Потоки продолжают проходить оба барьера, чтобы ни один участник не завис, но
оставшиеся вычисления пропускаются. После `join()` основной поток повторно
выбрасывает сохранённое исключение. Поэтому исключение из worker-функции не
приводит к `std::terminate`.

## Проверка отрицательных циклов и восстановление пути

После завершения потоков программа проверяет диагональ матрицы расстояний. Если
для какой-либо вершины выполняется `dist[i][i] < 0`, в графе присутствует
отрицательный цикл

Матрица `next` хранит следующую вершину кратчайшего пути. При улучшении
расстояния выполняется:

```cpp
next[i][j] = nextToK[i];
```

Метод `getPath()` последовательно переходит по `next` от начальной вершины к
конечной и возвращает полный маршрут.
