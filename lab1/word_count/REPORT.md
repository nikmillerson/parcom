# Отчёт по второй версии

Запуск:

```bash
./word_count <файл> [количество_слов=100] [число_потоков]
```

## Организация параллельной обработки

Файл читается частями по 256 КиБ. Функция `readBlock()` дочитывает последний
токен до пробельного символа, поэтому слово на границе двух блоков не
разрывается.

Рабочие потоки создаются один раз на весь файл. Каждый поток:

1. под `fileMutex` получает следующий блок из общего `ifstream`
2. освобождает мьютекс
3. параллельно с остальными потоками обрабатывает блок
4. записывает результат только в собственный локальный словарь

## Локальные словари

Для каждого потока заранее создаётся отдельный объект `WorkerData`:

```cpp
struct WorkerData {
    std::pmr::unsynchronized_pool_resource pool;
    LocalMap counts;
};
```

Объекты размещены раздельно через `std::unique_ptr`. Поток работает только со
своим `counts` и своим пулом, поэтому для подсчёта слов не нужны блокировки и
соседние изменяемые объекты не лежат подряд в одном `vector<map>`.

`std::pmr::unsynchronized_pool_resource` выдаёт память локальному словарю
крупными порциями. Это уменьшает количество обращений потоков к глобальному
аллокатору. К каждому пулу обращается только один поток подсчёта или одна задача слияния.

## Исправления по замечаниям

### Маленький непустой файл

Количество блоков теперь округляется вверх:

```cpp
const std::uintmax_t blockCount = 1 + (fileSize - 1) / BLOCK_SIZE;
threadCount = std::min<std::uintmax_t>(threadCount, blockCount);
```

Поэтому для любого непустого файла создаётся хотя бы один рабочий поток. Для
пустого файла `threadCount` равен нулю, что корректно: обрабатывать нечего.

### Параллельное объединение результатов

Общий `wordCountMap` и последовательное слияние под `resultMutex` удалены.
Локальные словари объединяются попарно:

- сначала одновременно `0 + 1`, `2 + 3`, ...;
- затем одновременно результаты соседних пар;
- шаги повторяются до получения одного словаря.

На каждом шаге задачи работают с непересекающимися парами словарей, поэтому
гонки данных нет и мьютекс для слияния не требуется. Число шагов равно
`O(log P)`, где `P` — количество рабочих потоков. Ключ копируется сразу в пул
словаря-получателя; временная `std::string` под общим мьютексом больше не
создаётся.

### Параллельная сортировка

Итоговый вектор делится на части. Части сортируются одновременно, после чего
попарно объединяются функцией `std::inplace_merge`. Таким образом, прежний
единственный последовательный вызов `std::sort` устранён.

### Исключения и завершение потоков

Тело каждого рабочего потока обёрнуто в `try/catch`. Первая ошибка сохраняется
в `std::exception_ptr`, защищённом `errorMutex`, и после завершения потоков
повторно выбрасывается в главном потоке. Флаг `failed` имеет тип
`std::atomic<bool>`.

Для `std::jthread` ручной `join()` удалён. Потоки автоматически присоединяются
при выходе из ограниченной области видимости. Исключения из задач слияния и
сортировки передаются через `std::future::get()`, поэтому они также не приводят
к необработанному исключению внутри потока.

## Синхронизация и отсутствие гонок

| Общие данные | Защита |
|---|---|
| `ifstream file` | чтение только под `fileMutex` |
| локальный `WorkerData` | во время подсчёта принадлежит одному потоку |
| пары словарей при слиянии | одна задача на непересекающуюся пару, между шагами вызывается `future::get()` |
| `failed` | атомарная переменная |
| `error` | `errorMutex` |
| части итогового вектора | задачи сортируют или объединяют непересекающиеся диапазоны |
