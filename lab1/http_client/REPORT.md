# Микроотчёт



## Что было добавлено

Создаётся заданное число рабочих потоков. Все они берут URL из общей очереди `toVisit`. Скачивание страницы и извлечение ссылок выполняются без удержания общего мьютекса, поэтому несколько HTTP-запросов могут идти одновременно.

Количество потоков задаётся третьим аргументом программы. По умолчанию используются четыре потока.

Для общей очереди и связанных с ней переменных используются:

- `std::mutex` — защищает очередь, множество уже добавленных URL, карту сайта и состояние завершения;
- `std::condition_variable` — усыпляет поток, когда очередь временно пуста;
- `pendingTasks` — число задач, которые находятся в очереди или уже выполняются.

Когда поток ставит новую ссылку в очередь, он увеличивает `pendingTasks`. После обработки своей страницы он уменьшает счётчик. Значение `0` означает, что очередь пуста и ни один поток больше не может обнаружить новые ссылки.

Проверяемое условие, изменение `pendingTasks`, изменение очереди и вызов `notify_all()` выполняются при захваченном одном и том же мьютексе. Поэтому поток не может проверить старое состояние между изменением счётчика и уведомлением и затем уснуть навсегда.

Ожидание записано с предикатом, который также защищает от ложных пробуждений.

```cpp
condition.wait(lock, [&]() {
    return stopped || !toVisit.empty() || pendingTasks == 0;
});
```

URL заносится в `visited` в момент постановки в очередь. Операция выполняется под мьютексом. Поэтому два потока не могут одновременно добавить одну и ту же страницу.

Исходный класс хранит сокет, `SSL_CTX` и `SSL` в полях объекта. Поскольку один такой объект нельзя одновременно использовать из нескольких потоков, то для каждого запроса создаётся отдельный локальный `HttpClient`. Сокеты и SSL-соединения между потоками не разделяются.

Глобальный вызов `EVP_cleanup()` убран из деструктора, чтобы один рабочий поток не очищал OpenSSL, пока другие потоки ещё выполняют HTTPS-запросы

Тело рабочего потока заключено в `try/catch`. Неожиданное исключение сохраняется в `std::exception_ptr`, устанавливается флаг остановки, ожидающие потоки пробуждаются, а основной поток сначала выполняет `join()`, а затем повторно выбрасывает исключение, что позволяет предотвратить `std::terminate` и зависание оставшихся потоков.

Ошибка загрузки отдельной страницы выводится в консоль и не мешает обработать остальные уже найденные страницы.

Ниже про нормализацию ссылок:

В исходном проекте относительная ссылка просто прибавлялась к текущему URL. Вместо этого используется `xmlBuildURI` из уже подключённой libxml2. Он корректно обрабатывает:

- абсолютные ссылки
- ссылки от корня
- относительные ссылки
- параметры запроса
- фрагменты вида `#section`

Ссылки `javascript:`, `mailto:` и `tel:` отбрасываются

После завершения потоков карта записывается в файл `sitemap.xml`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sitemap domain="example.com">
  <page url="https://example.com/">
    <link>https://example.com/about</link>
  </page>
</sitemap>
```

## Сборка

Сборка:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
```

## Запуск

```bash
./build/http_client <URL> [максимум_страниц] [число_потоков]
```
