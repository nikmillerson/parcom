# Микро-отчёт

Количество рабочих потоков определяется через
`std::thread::hardware_concurrency()` и ограничивается количеством вершин.
Каждый поток получает непрерывный блок строк матрицы:

```cpp
int begin = n * threadId / numThreads;
int end = n * (threadId + 1) / numThreads;
```

Непрерывные блоки уменьшают число границ между данными разных потоков по
сравнению с циклическим распределением строк.

## Устранение гонок данных

Одного барьера после итерации `k` недостаточно: во время вычислений одни потоки
могли изменять `dist[i][k]`, `dist[k][j]` и `next[i][k]`, пока другие их читали

Перед каждой параллельной итерацией основной поток создаёт три снимка:

```cpp
rowK[j] = dist[k][j];
columnK[i] = dist[i][k];
nextToK[i] = next[i][k];
```

Рабочие потоки читают только эти неизменяемые снимки, а записывают только строки
своего блока. Поэтому одновременного чтения и записи одного элемента `dist` или
`next` нет.

## Использование барьера

В барьере участвуют все рабочие потоки и основной поток:

```cpp
barrier syncPoint(numThreads + 1);
```

На каждой итерации `k` барьер используется дважды:

1. после подготовки снимков: рабочие потоки не начнут вычисления раньше
2. после обработки строк:  основной поток не начнёт следующую итерацию раньше

Таким образом, вычисление соответствует формуле:

```text
dist_new[i][j] = min(dist_old[i][j],
                     dist_old[i][k] + dist_old[k][j])
```
