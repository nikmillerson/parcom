# Микроотчёт

## Как устроен параллелизм в данном коде 

### 1. Чтение блоками

Размер обычного блока — 256 КиБ:

```cpp
constexpr std::size_t BLOCK_SIZE = 256 * 1024;
```

Функция `readBlock()` читает блок из общего файлового потока. Если граница попала внутрь слова, чтение продолжается до пробельного символа или конца файла. Поэтому слово на границе не разрывается и не теряется.

Файл целиком в память не загружается. У каждого потока находятся только текущий блок и свой словарь. Размер словарей зависит от количества различных слов. Один аномально длинный токен без пробелов может увеличить размер блока сверх 256 КиБ.

### 2. Динамическое распределение работы

Каждый рабочий поток повторяет следующие действия:

1. Захватывает `fileMutex` и читает очередной блок.
2. Освобождает `fileMutex`.
3. Обрабатывает свой блок и обновляет локальный словарь без блокировки.
4. Возвращается за следующим блоком.

Чтение из одного файлового потока последовательное, но обработка уже прочитанных блоков выполняется одновременно. Быстрее освободившийся поток получает следующий блок. Нет закрепления строк за потоками через `lineNumber % threadCount`.

Длинная строка, содержащая много слов, разбивается на несколько блоков и может обрабатываться несколькими потоками. Поэтому число строк не используется как ограничитель параллелизма.

### 3. Локальные словари и память

Внутри каждого рабочего потока создаются:

```cpp
std::pmr::unsynchronized_pool_resource pool;
LocalMap localMap{&pool};
```

`LocalMap` — это `std::map`, использующий локальный пул памяти:

```cpp
using LocalMap = std::pmr::map<std::pmr::string, std::uint64_t, std::less<>>;
```

Пул получает память крупными порциями и выдаёт из неё место под узлы словаря и символы ключей. Это уменьшает число обращений к общему аллокатору. Словарь =накапливает результат за всё время работы потока. Заново для каждого блока он не создаётся

Пул называется `unsynchronized`, потому что сам не защищается блокировками, потому что к конкретному пулу обращается только один поток.

Объекты словарей находятся внутри функций потоков

### 4. Подсчёт внутри блока

`toLower()` приводит к нижнему регистру сразу весь блок. `countWordsInBlock()` выделяет в нём слова через `std::string_view` представление участка строки без копирования символов.

`cleanWord()` принимает и возвращает `string_view`: очищает края слова, изменяя границы представления. Если слово уже есть в локальном словаре, увеличивается только счётчик. Если слова нет, в словаре создаётся собственная копия ключа из локального пула.

Словарь не хранит ссылки на временный блок: его ключи имеют тип `std::pmr::string`, поэтому живут независимо от обработки следующего блока.

### 5. Объединение результатов

Когда блоков больше нет, поток один раз захватывает `resultMutex` и добавляет весь свой словарь в итоговую `wordCountMap`. Блокировка удерживается на время слияния целого словаря

Слияния словарей выполняются последовательно. Остальные потоки в это время могут продолжать обрабатывать свои последние блоки. После `join()` основной поток преобразует итоговый словарь в вектор, сортирует и выводит результат.

При одинаковой частоте добавлен порядок по слову, чтобы результат не зависел от порядка завершения потоков. Счётчики имеют тип `std::uint64_t` вместо `int`.

## 6. Количество потоков

Число потоков берётся из аргумента командной строки или `hardware_concurrency()`. Если система возвращает ноль, используется один поток.

Дополнительно число потоков ограничивается объёмом файла: ориентировочно не менее 256 КиБ входных данных на поток. Для маленького непустого файла создаётся один поток, для пустого — ни одного.

Для приложенного Alchemist размером 890 979 байт максимальное число потоков по этому правилу равно трём, даже если запросить четыре или больше.

Это ограничение по объёму полезной работы, а не точная гарантия отсутствия простоя: длительность обработки блоков может различаться, а токен длиннее блока не делится. Создавать много потоков для единственного огромного слова невыгодно; такой крайний случай не используется как критерий ускорения.
